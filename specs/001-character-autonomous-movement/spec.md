# Feature Specification: 캐릭터 자율 이동

**Feature Branch**: `001-character-autonomous-movement`

**Created**: 2026-10-22

**Status**: Draft

**Input**: User description: "캐릭터 자율 이동"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 캐릭터가 스스로 화면을 돌아다닌다 (Priority: P1)

사용자가 앱을 실행하면 캐릭터가 데스크탑 화면 위에 나타나고, 사용자가 아무것도 하지 않아도
스스로 이동한다. 걷다가 멈추고, 다시 다른 방향으로 걷는 식으로 살아 있는 듯 움직인다.

**Why this priority**: 자율 이동은 제품 정체성(화면 위를 돌아다니는 캐릭터)의 최소 가치이며,
이것만 있어도 독립적으로 데모할 수 있는 MVP다.

**Independent Test**: 앱을 실행하고 입력 없이 1분간 관찰해 캐릭터가 여러 위치로 이동하는지
확인한다.

**Acceptance Scenarios**:

1. **Given** 앱이 실행된 직후, **When** 사용자가 아무 입력도 하지 않으면, **Then** 캐릭터가
   화면 위에 나타나 스스로 이동하기 시작한다.
2. **Given** 캐릭터가 이동 중일 때, **When** 일정 시간이 지나면, **Then** 캐릭터는 멈추거나
   방향을 바꾸며 한 방향으로만 끝없이 이동하지 않는다.
3. **Given** 캐릭터가 이동 중일 때, **When** 화면 가장자리에 도달하면, **Then** 화면 밖으로
   나가지 않고 방향을 바꾼다.

---

### User Story 2 - 작업을 방해하지 않고 이동한다 (Priority: P2)

사용자가 다른 앱에서 작업하는 동안 캐릭터가 돌아다녀도, 캐릭터가 없는 영역의 클릭과 입력은
그대로 아래 창에 전달된다.

**Why this priority**: 헌장의 비침습성 원칙. 상시 실행되는 앱이므로 작업 방해는 곧 삭제로
이어진다.

**Independent Test**: 다른 앱 창을 띄우고 캐릭터가 이동하는 중에 캐릭터가 없는 영역을
클릭·입력해 정상 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 캐릭터가 이동 중일 때, **When** 사용자가 캐릭터가 없는 영역을 클릭하면, **Then**
   클릭은 아래 창에 정상 전달된다.
2. **Given** 캐릭터가 이동 중일 때, **When** 사용자가 다른 앱을 사용하면, **Then** 해당 앱의
   포커스와 입력이 유지된다.

---

### User Story 3 - 사용자 조작 중에는 자율 이동을 멈춘다 (Priority: P3)

사용자가 캐릭터를 롱프레스로 잡거나 우클릭 메뉴를 열면 캐릭터는 자율 이동을 멈추고,
조작이 끝나면 그 위치에서 자율 이동을 재개한다.

**Why this priority**: 자율 이동이 다른 핵심 상호작용(롱프레스 이동, 우클릭 메뉴)을 깨뜨리지
않아야 한다는 헌장 원칙 II를 충족하기 위함이다. 두 상호작용 자체의 스펙은 별도 기능이다. 이번 기능에서는 상태 전이(엔진 수준)까지만 구현·검증하며,
롱프레스·우클릭 메뉴를 통한 실제 조작 검증(SC-004 종단 확인)은 해당 기능에서 한다.

**Independent Test**: 이동 중인 캐릭터를 잡거나 우클릭했을 때 이동이 멈추는지, 놓거나 메뉴를
닫으면 재개되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 캐릭터가 이동 중일 때, **When** 사용자가 캐릭터를 롱프레스로 잡으면, **Then**
   자율 이동이 즉시 멈춘다.
2. **Given** 캐릭터가 사용자 조작으로 멈춰 있을 때, **When** 조작이 끝나면, **Then** 캐릭터는
   현재 위치에서 자율 이동을 재개한다.

---

### Edge Cases

- 화면 해상도나 모니터 구성이 바뀌면(모니터 연결·해제) 캐릭터가 사라진 영역에 갇히지 않고
  남은 화면 안으로 복귀한다.
- 멀티 모니터 환경에서 캐릭터가 모니터 사이를 오갈 수 있다.
- 작업 표시줄·메뉴 막대·Dock 영역 위에서도 캐릭터가 보이고 사용자가 조작할 수 있다.
- 전체 화면 앱이 실행 중일 때 캐릭터가 사용자의 전체 화면 사용을 방해하지 않는다.
- 시스템이 절전에서 복귀한 뒤에도 캐릭터가 정상적으로 이동을 재개한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 앱 실행 시 캐릭터를 데스크탑 화면 위에 표시해야 한다.
- **FR-002**: 시스템은 사용자 입력 없이 캐릭터를 스스로 이동시켜야 한다.
- **FR-003**: 캐릭터의 이동은 이동과 정지를 번갈아 해야 하며, 1분 관찰 동안 정지가 2회 이상
  있고 이동 방향이 3회 이상 바뀌어야 한다.
- **FR-004**: 캐릭터는 연결된 모든 화면 전체(작업 표시줄·메뉴 막대·Dock 영역 포함)를 이동할 수
  있고, 이동 가능 영역 밖으로 나가지 않아야 한다.
- **FR-005**: 캐릭터가 없는 영역의 클릭과 입력은 아래 창에 그대로 전달되어야 한다.
- **FR-006**: 사용자가 캐릭터를 롱프레스로 잡거나 우클릭 메뉴를 열면 자율 이동은 즉시 멈춰야
  하고, 조작이 끝나면 현재 위치에서 재개되어야 한다.
- **FR-007**: 자율 이동은 macOS와 Windows에서 동일하게 동작해야 한다.
- **FR-008**: 모니터 구성이 바뀌어도 캐릭터는 항상 보이는 이동 가능 영역 안에 있어야 한다.

### Key Entities

- **캐릭터**: 화면 위에 표시되는 대상. 현재 위치, 이동 방향, 상태(이동 중 / 정지 / 사용자 조작
  중)를 가진다.
- **이동 가능 영역**: 캐릭터가 위치할 수 있는 화면 영역. 연결된 모니터 구성에 따라 달라진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 앱 실행 후 사용자 입력 없이 5초 안에 캐릭터가 이동을 시작한다.
- **SC-002**: 입력 없이 10분간 관찰해도 캐릭터가 화면 밖으로 벗어나거나 한 지점에 영구히
  멈추지 않는다.
- **SC-003**: 수동 검증에서 캐릭터 근처 영역을 20회 클릭했을 때 20회 모두 아래 창에 정상
  전달된다.
- **SC-004**: 사용자가 캐릭터를 잡거나 메뉴를 연 순간부터 0.5초 안에 자율 이동이 멈춘다.
- **SC-005**: 두 지원 OS(macOS, Windows) 모두에서 위 기준을 모두 충족한다.
- **SC-006**: 유휴 상태에서 평균 CPU 사용률이 3% 이하이고 메모리 사용량이 300MB 이하이다.
- **SC-007**: 캐릭터 애니메이션이 초당 30프레임 이상으로 부드럽게 보인다.

## Assumptions

- 사용자는 단일 또는 다중 모니터 데스크탑 환경에서 앱을 사용한다.
- 캐릭터 이동은 평면(좌우·상하) 이동이며, 창 위에 올라타거나 창과 충돌하는 동작은 이번
  범위에 포함하지 않는다.
- 이동 속도, 정지 간격 등 구체적 값은 plan 단계에서 정하며, 사용자 설정 기능은 이번
  범위에 포함하지 않는다.
- 캐릭터는 코드로 그리는 폴리곤 도형(AI가 제작한 임시 디자인) 하나이며, 걷기와 정지 두 가지
  모습을 가진다. 최종 디자인과 외부 이미지 에셋은 별도 기능에서 정의한다.
- 롱프레스 이동과 우클릭 메뉴 자체는 별도 기능이며, 이 스펙은 두 상호작용과 공존하는
  동작(FR-006)만 다룬다.
