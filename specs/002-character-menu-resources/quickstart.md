# 퀵스타트: 우클릭 메뉴와 캐릭터 리소스 설정 검증

기능이 끝까지 동작하는지 확인하는 절차다. 구현 코드는 포함하지 않는다. 구조는
[plan.md](./plan.md), 상태 모델은 [data-model.md](./data-model.md), 계약은
[contracts/ipc.md](./contracts/ipc.md), [contracts/storage.md](./contracts/storage.md)를 따른다.

## 사전 준비

- 001과 같음(Node.js LTS, npm, macOS). 검증용 이미지는 저장소의 `src/renderer/assets/walk.png`(8프레임),
  `idle.png`를 쓴다. 조건 위반 확인용 파일은 아래 표의 설명대로 직접 만든다.

## 실행

```bash
npm install
npm run dev          # 개발 실행
npm test             # 단위 테스트
npm run test:e2e     # E2E (설정 창을 자동으로 연다)
KAKARU_USER_DATA=/tmp/kakaru-test npm run dev   # 저장 데이터를 임시 폴더로 격리
```

설정 창만 바로 열려면 앱 인자로 `--open-settings`를 준다(개발·테스트용).

## 자동 검증 (기대 결과)

- 단위: 이미지 검증 규칙(9가지 오류 코드), PNG 헤더 파싱, `CharacterStore`(등록·삭제·활성 변경·손상
  복구·원자적 쓰기), 메뉴 상태(열림·닫힘·중복 열림 방지, `setUserControlled` 호출).
- E2E: 설정 창에서 이미지를 선택·등록하면 목록에 나타나고, 적용하면 오버레이가
  `character:appearance`를 받는다. 앱을 다시 실행해도 활성 캐릭터가 유지된다.

## 수동 검증

| # | 절차 | 기대 결과 | 관련 |
|---|---|---|---|
| 1 | 캐릭터를 우클릭 | 0.5초 안에 메뉴가 열리고 캐릭터가 멈춘다. 항목은 "캐릭터 설정" | US1, SC-001 |
| 2 | 메뉴 밖을 클릭하거나 Esc | 메뉴가 닫히고 1초 안에 같은 자리에서 다시 이동한다 | US1, SC-002 |
| 3 | 캐릭터가 없는 영역을 우클릭 20회 | 메뉴가 열리지 않고 아래 앱에 우클릭이 전달된다 | FR-002, SC-003 |
| 4 | 화면 가장자리·모서리에서 우클릭 | 메뉴가 잘리지 않고 전체가 보인다 | FR-005 |
| 5 | 메뉴가 열린 상태에서 캐릭터를 다시 우클릭 | 메뉴가 하나만 유지된다 | FR-005 |
| 6 | 전체 화면 앱 위에서 캐릭터를 우클릭 | 메뉴가 열리고 닫으면 이전 상태로 돌아온다 | 엣지 케이스 |
| 7 | "캐릭터 설정" 선택 | 설정 창이 열리고 이미 열려 있으면 앞으로 나온다 | US1 |
| 8 | 올바른 이미지로 등록(2분 안에) | 목록에 나타난다. 미리보기에서 걷기 반복·정지가 보인다 | US2, SC-004 |
| 9 | 조건 위반 이미지 10종 등록 시도 | 10종 모두 등록되지 않고 이유가 보인다 | FR-010, SC-005 |
| 10 | 등록한 캐릭터를 선택 | 2초 안에 화면 위 캐릭터가 바뀌고 위치·방향은 유지된다 | US3, SC-006 |
| 11 | 앱을 종료 후 다시 실행 10회 | 마지막에 선택한 캐릭터가 매번 유지된다 | FR-012, SC-007 |
| 12 | 사용 중인 캐릭터를 삭제, 기본으로 되돌리기 | 기본 캐릭터로 바뀌고 기본은 삭제 버튼이 없다 | FR-013, FR-014 |
| 13 | 활성 캐릭터의 이미지 파일을 직접 지우고 앱 실행 | 기본으로 표시되고 설정 화면에 문제가 표시된다 | FR-015 |

조건 위반 이미지 10종: JPEG 파일, 5MB 초과 파일, 손상된 PNG, 프레임 수 0과 40, 너비가
`높이×프레임 수`가 아닌 걷기 이미지, 정사각형이 아닌 정지 이미지, 불투명 배경 이미지, 빈 이름과
중복 이름.
