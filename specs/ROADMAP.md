# Kakaru 로드맵과 현재 상태

마지막 갱신: 2026-10-22. 새 세션은 이 문서와 `CLAUDE.md`, 헌장(`.specify/memory/constitution.md`)부터 읽는다.
**이 문서는 확정된 계획이 아니라 지금까지 나온 정보의 정리다.** 제품 방향은 아직 정해지지 않았다(아래 "결정이 필요한 것").

## 한 줄 정의

데스크탑(macOS·Windows) 화면 위를 캐릭터가 돌아다니고, 사용자가 상호작용할 수 있는 앱. 핵심 상호작용 3종(헌장 원칙 II): **자율 이동, 끌어서 옮기기, 우클릭 메뉴로 기능 사용**.

## 완료한 기능 (모두 macOS에서 검증, Windows는 후속)

| spec | 내용 | 비고 |
|---|---|---|
| `001-character-autonomous-movement` | 캐릭터 자율 이동(걷기·정지·방향 전환), 디스플레이별 투명 오버레이, 클릭 통과, 모니터 변경·절전 복귀 대응 | CPU 유휴 평균 약 8%(기준 10% 이하) |
| `002-character-menu-resources` | 우클릭 네이티브 메뉴(열림 중 이동 정지), 캐릭터 설정 창(이미지 등록·검증·선택·삭제·기본 복귀), 샘플 캐릭터 "빨간 모자" 자동 등록 | 단위 109+, E2E 14 |
| `003-menu-quit-zoom` | 메뉴에 종료·확대·축소 추가, 크기 저장·한계에서 항목 비활성화 | 한 단계 0.2배, 범위 0.5~3배(확정) |
| `004-character-drag-move` | 캐릭터를 누른 채 끌어 옮기기(잡은 지점 유지, 디스플레이 영역으로 제한, 놓으면 그 자리에서 재개) | 자동 검증 통과, 수동 검증 대기(macOS) |
| `005-speech-bubble-monologue` | 머리 위 말풍선과 혼잣말(분류별 문장 무작위 선택, 문장은 캐릭터마다 `lines.json`), 잡았을 때·오래 잡았을 때 대사 | 자동 검증 통과, 수동 검증 대기(macOS) |
| `006-dialogue-settings` | 설정 창에서 캐릭터별 대사 편집(분류별 문장 추가·수정·삭제, 입력 검증, 처음 문장으로 되돌리기·모두 비우기, 기본 캐릭터 편집본 `default-lines.json`) | 자동 검증 통과, 수동 검증 대기(macOS) |

## 다음에 할 수 있는 것 (우선순위 제안)

1. **Windows 검증** — 코드는 두 OS를 지원하도록 만들었지만 한 번도 실행하지 않았다. `tests/manual/results.md`의 001·002·003 표(Windows 열 "후속")를 채운다. 함께 확인: 멀티 모니터(연결·해제), 절전 복귀, `focusable: false` 오버레이의 `context-menu` 발생, 작업 표시줄 위 표시, CPU·메모리 측정.
2. **투명 배경 검사 강화** — 지금은 알파가 255가 아닌 픽셀이 하나만 있어도 통과한다(모서리 한 픽셀만 투명한 흰 배경 이미지도 통과). 가장자리 비율 검사 등을 추가하는 개선. 제안 단계이고 spec은 없다.
3. **최종 캐릭터 디자인 교체** — 현재 기본은 폴리곤 고양이(임시), 샘플은 `specs/bmm.png`에서 잘라 낸 이미지. 같은 파일명·규격으로 교체하면 된다(규격은 `README.md`).
4. **상태별 이미지 추가** — 집힌 모습(드래그), 메뉴가 열린 동안의 모습. 지금은 모두 정지 이미지로 대체.
5. **3D·물리** — 헌장에 "추후 도입"으로만 있다. 후보는 Three.js(렌더링), Rapier(물리). 시점·범위 미정. 도입하면 오버레이 렌더링 구조(현재 `<img>`+CSS)를 다시 설계해야 한다.

## 범위 밖으로 미뤄 둔 작은 것들

- 002: 캐릭터 이름 변경·순서 변경, 내보내기·공유, 프레임 애니메이션 편집기, 이미지 편집
- 003: 메뉴를 연 채 연속 확대, 마우스 휠·단축키로 확대·축소
- 화면 가장자리에서 확대하면 캐릭터 일부가 화면 밖에 걸친다(위치는 중심 기준, 크기 반영해 가두지 않음)

## 아직 없는 것 (기능이 아닌 빈칸)

- **패키징·배포**: electron-builder 등을 도입하지 않았다. 설치 파일, 앱 아이콘, 로그인 시 자동 실행, 코드 서명·공증(macOS) 모두 없다.
- **트레이·Dock 아이콘**: Dock과 메뉴 막대에 앱이 보이지 않는다(종료는 우클릭 메뉴로만 가능).
- **사용자용 안내 문서**: README는 개발자용이다.

## 결정이 필요한 것

- **제품 방향**: 캐릭터가 이동·메뉴·모습 설정 외에 무엇을 하는 앱인지(대사·알림·반응·미니 기능 등) 정해지지 않았다. 지금 기능은 모두 기반 기능이다.
- Windows 검증을 누가·언제 할지
- 배포 대상(개인 사용인지, 배포할 앱인지)에 따라 패키징 우선순위가 달라진다

## 기술 현황 요약

- 스택: Electron + TypeScript + electron-vite, Vitest(단위), Playwright(Electron E2E). 렌더링은 `<img>`+CSS(canvas 아님).
- 구조·함정·작업 규칙은 `CLAUDE.md`. 설계 결정은 각 `specs/NNN-*/research.md`.
- 저장: `~/Library/Application Support/kakaru/settings.json` + `characters/<id>/`. 형식은 `specs/002-character-menu-resources/contracts/storage.md`(`seeded`, `scale` 필드 포함).
- 수동 검증 기록: `tests/manual/results.md`.
