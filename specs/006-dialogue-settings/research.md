# Research: 대사 설정 화면

## R1. 편집 UI: 분류별 텍스트 영역(한 줄 = 한 문장)

- **Decision**: 분류마다 `<textarea>` 하나. 줄바꿈이 문장 구분이다. 줄마다 규칙을 검사해 위반한 줄 번호·글자 수·이유를 영역 아래에 나열하고, 분류 상단에 `현재 개수/50`을 보인다.
- **Rationale**: 추가·수정·삭제를 한 입력으로 해결하고(FR-002), 줄바꿈 처리(FR-006)와 자연스럽게 맞는다. 줄별 입력칸·삭제 버튼 목록보다 코드가 훨씬 작다(헌장 IV).
- **Alternatives**: 문장마다 입력칸+삭제 버튼(상호작용 복잡, 50개 목록 렌더링).
- **Spec 영향**: US2 시나리오 3("51번째 추가 시 추가되지 않음")은 텍스트 영역 모델에서는 "50개를 넘으면 초과 이유가 보이고 저장할 수 없다"로 구현한다. 차단 대신 오류 표시이며 결과(저장 불가, 이유 노출)는 같다. spec에 반영한다.

## R2. 검증 규칙은 shared의 순수 함수 하나

- **Decision**: `validateLinesInput(input: Record<Category, string[]>)`가 줄바꿈 분할 → 앞뒤 공백 제거 → 빈 문장 제외(개수 기록) → 중복 제거(개수 기록) → 길이·개수 검사를 하고 `{ ok, lines, issues, dropped, merged }`를 돌려준다. 렌더러(입력 중)와 메인(저장 직전)이 같은 함수를 쓴다. 005의 `sanitizeLines`와 규칙 상수(`config.speech`)를 공유한다.
- **Rationale**: 규칙이 두 곳에 있으면 어긋난다. 메인 재검증은 렌더러를 신뢰하지 않기 위한 것이다.
- **issues 형태**: `{ category, line: number /* 1부터, 원본 입력 기준 */, code: 'too-long' | 'too-many', message }`. 화면은 줄 번호로 안내한다.

## R3. 저장 위치

- **Decision**: 등록·샘플 캐릭터는 기존 `characters/<id>/lines.json`에 쓴다. 기본 캐릭터는 `<userData>/default-lines.json`(같은 형식)에 쓰고, 읽을 때 이 파일이 유효하면 그것을, 없거나 깨졌으면 내장 `DEFAULT_LINES`를 쓴다.
- **Rationale**: 005의 읽기 경로(`readLines`)와 형식을 그대로 재사용한다. 기본 캐릭터는 캐릭터 폴더가 없으므로 루트에 별도 파일을 둔다. 유효한 편집본이 모두 비어 있으면 "말하지 않음"으로 받아들인다(사용자가 의도적으로 비운 것).
- **Alternatives**: `settings.json`에 포함(스키마 버전 변경 필요).

## R4. 처음 문장으로 되돌리기

- **Decision**: 기본 캐릭터는 `default-lines.json`을 삭제한다. 샘플 캐릭터는 샘플 폴더의 `lines.json`을 캐릭터 폴더에 다시 복사한다. 샘플 여부는 설치 기록(`seeded` 키)과 이름 일치로 판단한다(005 백필과 같은 방식). 등록 캐릭터는 되돌리기 대신 "모두 비우기"(빈 대화셋 저장).
- **Rationale**: 앱에 들어 있는 원본은 항상 남아 있으므로 복원은 복사 또는 삭제로 끝난다.
- **한계**: 샘플 이름과 같은 이름으로 사용자가 직접 등록한 캐릭터는 샘플로 오인될 수 있다. 개인 사용에서는 허용(005와 동일).

## R5. 원자적 저장과 실패 처리

- **Decision**: `lines.json.tmp`에 쓴 뒤 `rename`한다. 실패하면 임시 파일을 지우고 오류를 돌려주며, 화면의 입력은 그대로 둔다. 저장 전에 캐릭터가 존재하는지 확인하고(`list()`에 없으면 거부, FR-011), 기본 캐릭터(`null`)는 항상 존재한다.
- **Rationale**: 기존 `settings.json` 저장 방식(tmp → rename)과 같다.

## R6. 즉시 반영

- **Decision**: 별도 알림 없이 둔다. 발화 시점마다 `readLines()`가 파일을 읽으므로 다음 발화부터 새 문장이 쓰인다.
- **Rationale**: 005에서 이미 그렇게 만들었고 읽는 빈도가 낮다(수십 초에 한 번).

## R7. 화면 전환과 미저장 확인

- **Decision**: 같은 설정 창 오른쪽 영역에서 "새 캐릭터 등록" 폼과 "대사 편집" 패널을 전환한다. 미저장 변경이 있을 때 패널을 닫거나 다른 캐릭터로 이동하면 패널 상단에 인라인 막대(저장 / 버리기 / 계속 편집)를 보인다. 창 자체 닫기 확인은 하지 않는다.
- **Rationale**: `window.confirm`은 두 가지 선택만 줄 수 있어 세 선택지를 못 낸다. 새 창이나 대화상자 모듈을 만들지 않고 인라인으로 처리한다.
- **한계**: 설정 창을 닫을 때의 미저장 경고는 범위 밖이다(spec FR-007은 "화면을 닫거나 다른 캐릭터로 이동"을 다루며 창 닫기는 포함하지 않음).

## R8. 목록 변경과의 동기화

- **Decision**: 편집 중인 캐릭터가 삭제되면(`characters:changed` 알림 후 목록에 없음) 패널에 안내하고 저장을 비활성화한다. 저장 요청은 메인이 존재 여부를 다시 확인한다.
- **Rationale**: FR-011, 기존 변경 알림 채널을 재사용한다.
