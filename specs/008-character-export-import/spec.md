# Feature Specification: 캐릭터 내보내기·가져오기

**Feature Branch**: `008-character-export-import` (브랜치는 만들지 않는다. `main` 유지)

**Created**: 2026-10-22

**Status**: 구현 완료, macOS 수동 검증 대기

**Input**: User description: "캐릭터 추출이랑 그거 갖다가 쓰는 기능 추가. 대사도 포함" — "갖다 쓴다"는 내보낸 파일을 바탕으로 캐릭터를 새로 추가하는 것이다.

설정 창의 캐릭터 목록에서 캐릭터 하나를 파일 하나로 내보내고, 그 파일로 다른 데스크탑(또는 같은 데스크탑)에 새 캐릭터를 추가한다. 이미지와 대사가 함께 옮겨진다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 캐릭터를 파일로 내보낸다 (Priority: P1)

사용자가 설정 창의 캐릭터 목록에서 등록된 캐릭터를 골라 "내보내기"를 누르고 저장 위치를 정하면, 그 캐릭터의 걷기·정지 이미지와 대사가 담긴 `.kakaru` 파일 하나가 만들어진다.

**Why this priority**: 파일이 있어야 옮기든 백업하든 할 수 있다. 가져오기의 전제다.

**Independent Test**: 설정 창에서 "나" 캐릭터를 내보내면 `.kakaru` 파일이 저장 위치에 생기고, 앱의 캐릭터·대사는 그대로다.

**Acceptance Scenarios**:

1. **Given** 등록된 캐릭터가 있을 때, **When** 목록에서 그 캐릭터의 "내보내기"를 누르고 저장 위치와 파일 이름을 정하면, **Then** `.kakaru` 파일 하나가 만들어지고 완료 메시지가 보인다. 기본 파일 이름은 캐릭터 이름이다.
2. **Given** 내보내기 저장 창이 열렸을 때, **When** 사용자가 취소하면, **Then** 파일은 만들어지지 않고 오류 메시지도 없다.
3. **Given** 같은 이름의 파일이 저장 위치에 이미 있을 때, **When** 저장하면, **Then** 운영체제의 덮어쓰기 확인을 따른다.
4. **Given** 목록에 기본 캐릭터(폴리곤 고양이)가 있을 때, **When** 목록을 보면, **Then** 기본 캐릭터에는 내보내기 버튼이 없다.
5. **Given** 대사를 편집한 캐릭터를 내보냈을 때, **When** 그 파일을 가져오면, **Then** 편집한 대사 전체(네 분류)가 그대로 따라온다.

---

### User Story 2 - 파일로 새 캐릭터를 추가한다 (Priority: P1)

사용자가 설정 창에서 "가져오기"를 눌러 `.kakaru` 파일을 고르면, 파일에 담긴 이미지와 대사로 새 캐릭터가 목록에 추가된다. 가져온 캐릭터는 자동으로 적용되지 않고 목록에서 직접 고른다.

**Why this priority**: 내보내기만으로는 쓸 곳이 없다. 두 기능이 한 쌍이다.

**Independent Test**: 다른 사용자 데이터 폴더(`KAKARU_USER_DATA`)에서 앱을 띄우고 내보낸 파일을 가져오면 같은 이름·이미지·대사의 캐릭터가 목록에 생긴다.

**Acceptance Scenarios**:

1. **Given** 유효한 `.kakaru` 파일이 있을 때, **When** "가져오기"로 그 파일을 고르면, **Then** 새 캐릭터가 목록에 추가되고 이름·이미지·대사가 파일과 같으며 완료 메시지가 보인다.
2. **Given** 같은 파일을 두 번 가져왔을 때, **When** 두 번째 가져오기가 끝나면, **Then** 기존 캐릭터는 그대로 있고 새 캐릭터가 하나 더 생긴다(덮어쓰지 않는다).
3. **Given** 가져오기 파일 선택 창이 열렸을 때, **When** 사용자가 취소하면, **Then** 아무 변화도 없고 오류 메시지도 없다.
4. **Given** 캐릭터를 가져왔을 때, **When** 목록을 보면, **Then** 현재 적용 중이던 캐릭터는 바뀌지 않는다. 사용자가 목록에서 "적용"을 눌러야 바뀐다.
5. **Given** 내보낸 캐릭터의 이름이 이미 목록에 있는 이름일 때, **When** 가져오면, **Then** 이름 뒤에 " (2)"처럼 번호를 붙여 구분되는 이름으로 등록한다(2부터 비어 있는 첫 번호). 기존 등록 규칙(이름은 목록에서 겹치지 않는다)을 유지한다.

---

### User Story 3 - 잘못된 파일은 거부하고 이유를 알려 준다 (Priority: P2)

규격에 맞지 않거나 손상된 파일은 가져오지 않고, 사용자가 고칠 수 있게 이유를 보여 준다.

**Why this priority**: 손으로 만지거나 다른 버전에서 온 파일이 앱의 저장 데이터를 망가뜨리면 안 된다.

**Independent Test**: 이미지 크기가 맞지 않게 고친 파일, JSON이 깨진 파일, 확장자만 `.kakaru`인 임의 파일을 가져오면 모두 거부 메시지가 나오고 목록이 그대로다.

**Acceptance Scenarios**:

1. **Given** 파일 안의 이미지가 기존 이미지 등록 규격(크기·형식·투명 배경)을 어길 때, **When** 가져오면, **Then** 가져오지 않고, 이미지 등록 때와 같은 이유 문구를 보여 준다.
2. **Given** 파일 안의 대사가 대사 설정의 규칙(문장 길이·분류당 개수)을 어길 때, **When** 가져오면, **Then** 가져오지 않고 어느 분류가 왜 어긋났는지 보여 준다.
3. **Given** 파일이 손상됐거나 `.kakaru` 형식이 아닐 때, **When** 가져오면, **Then** "캐릭터 파일이 아니거나 손상됐다"는 뜻의 메시지를 보이고 목록은 그대로다.
4. **Given** 이 앱보다 새 버전에서 만든 파일(알 수 없는 파일 형식 버전)일 때, **When** 가져오면, **Then** 거부하고 "지원하지 않는 버전"이라는 뜻의 메시지를 보인다.
5. **Given** 가져오기가 도중에 실패했을 때, **When** 목록을 보면, **Then** 반쯤 만들어진 캐릭터가 남지 않는다.

### Edge Cases

- 대사가 모두 비어 있는 캐릭터도 내보내고 가져올 수 있다(등록한 캐릭터의 기본 상태).
- 가져온 파일의 이름이 비었거나, 30자를 넘거나, 예약 이름("기본")이면 거부한다(기존 등록 화면과 같은 규칙). 겹치는 이름은 거부하지 않고 번호를 붙인다. 번호를 붙여 30자를 넘으면 앞부분을 줄여 맞춘다.
- 내보내기는 저장돼 있는 대사를 담는다. 대사 편집 화면에서 아직 저장하지 않은 입력은 담기지 않는다.
- 파일 하나에는 캐릭터 하나만 담긴다. 여러 캐릭터를 한 번에 내보내거나 가져오지 않는다.
- 내보내는 동안 설정 창을 닫거나 앱을 종료해도 저장 데이터는 손상되지 않는다.
- 파일에는 컴퓨터 경로·사용자 이름 등 개인 환경 정보를 넣지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자는 설정 창의 캐릭터 목록에서 등록된 캐릭터 하나를 골라 `.kakaru` 파일 하나로 내보낼 수 있어야 한다(MUST). 저장 위치와 파일 이름은 사용자가 정한다.
- **FR-002**: 내보낸 파일에는 캐릭터 이름, 걷기 이미지, 정지 이미지, 프레임 수·프레임 크기, 대사 네 분류 전체가 들어야 한다(MUST). 현재 적용 여부·생성 시각·내부 식별자·저장 경로는 넣지 않는다.
- **FR-003**: 기본 캐릭터(폴리곤 고양이)는 내보내기 대상이 아니다. 목록에서 내보내기 버튼을 보이지 않는다(MUST).
- **FR-004**: 사용자는 설정 창에서 `.kakaru` 파일을 골라 새 캐릭터를 추가할 수 있어야 한다(MUST). 가져온 캐릭터는 항상 새 캐릭터로 등록되며 기존 캐릭터를 덮어쓰거나 바꾸지 않는다. 이름이 겹치면 번호를 붙여 구분한다.
- **FR-005**: 가져온 캐릭터는 자동으로 적용하지 않는다. 현재 적용 중인 캐릭터는 그대로 유지한다(MUST).
- **FR-006**: 가져오기는 파일 안의 이미지에 기존 이미지 등록과 같은 검증을, 대사에 기존 대사 설정과 같은 검증을 적용해야 한다(MUST). 하나라도 실패하면 아무것도 등록하지 않는다.
- **FR-007**: 거부할 때는 원인을 사용자가 알 수 있는 문구로 보여 준다(MUST): 이미지 규격 위반, 대사 규칙 위반, 손상·비대상 파일, 지원하지 않는 버전.
- **FR-008**: 가져오기·내보내기를 취소하면 저장 데이터와 화면은 변하지 않고 오류도 보이지 않는다(MUST).
- **FR-009**: 가져오기에 실패하거나 중단되면 부분적으로 만들어진 캐릭터가 남지 않아야 한다(MUST).
- **FR-010**: 이 기능은 새 외부 의존성(라이브러리)을 추가하지 않는다(MUST NOT 추가). 헌장 IV(단순성)에 따른다.
- **FR-011**: 이 기능은 핵심 상호작용 3종(자율 이동·드래그·우클릭 메뉴)과 오버레이 동작에 영향을 주지 않는다(MUST). 변경은 설정 창과 저장소에 한정된다.
- **FR-012**: 두 기능 모두 macOS와 Windows에서 동일하게 동작해야 한다(MUST). 이번 검증은 macOS에서 한다.

### Key Entities

- **캐릭터 파일(.kakaru)**: 캐릭터 하나를 옮기기 위한 이식용 파일. 형식 버전, 캐릭터 이름, 프레임 수·크기, 걷기·정지 이미지, 대사 네 분류를 가진다.
- **캐릭터**: 앱에 등록된 기존 개념(이름, 걷기·정지 이미지, 대사). 가져오기로 새 식별자를 받아 하나 더 생긴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 내보낸 파일을 가져오면 이름·두 이미지·네 분류의 대사가 원본과 모두 같은 캐릭터가 생긴다(항목 100% 일치).
- **SC-002**: 사용자는 내보내기를 3번 이하의 조작(버튼, 위치 선택, 저장)으로, 가져오기를 3번 이하의 조작(버튼, 파일 선택, 확인)으로 끝낸다.
- **SC-003**: 규격에 맞지 않는 파일 5종(이미지 규격 위반, 대사 규칙 위반, 손상, 비대상, 새 버전)이 모두 거부되고, 거부 뒤 캐릭터 목록·저장 데이터는 가져오기 전과 같다.
- **SC-004**: 같은 파일을 여러 번 가져와도 기존 캐릭터가 변하지 않고, 가져온 횟수만큼 서로 다른 이름의 새 캐릭터가 늘어난다.
- **SC-005**: 기존 캐릭터 등록·삭제·대사 편집과 핵심 상호작용 3종의 기존 테스트가 그대로 통과한다.

## Assumptions

- "추출"은 내보내기, "갖다 쓴다"는 파일로 새 캐릭터를 추가하는 가져오기로 해석했다. 같은 id면 덮어쓰기·병합하는 동작은 범위 밖이다.
- 파일 형식은 `.kakaru` 단일 파일이다(추천안 1a, 사용자 진행 승인). 압축 파일·폴더 내보내기는 범위 밖이다.
- 진입점은 설정 창 캐릭터 목록이다(우클릭 메뉴에는 항목을 추가하지 않는다).
- 기본 캐릭터의 편집한 대사(`default-lines.json`)는 이번 범위에서 내보내지 않는다. 필요하면 후속 기능으로 한다.
- 한 번에 파일 하나, 캐릭터 하나만 처리한다.
- 파일을 사람이 열어 고치거나 다른 도구로 만드는 것은 지원 대상이 아니지만, 그런 파일도 검증을 통과하면 가져올 수 있다.
- 샘플 캐릭터("빨간 모자", "나")는 일반 등록 캐릭터와 같이 내보낼 수 있다.
- 이번 검증은 macOS에서 수행한다. Windows는 후속이다.
