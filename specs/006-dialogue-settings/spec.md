# Feature Specification: 대사 설정 화면

**Feature Branch**: `006-dialogue-settings`

**Created**: 2026-10-22

**Status**: 구현 완료, macOS 수동 검증 대기

**Input**: User description: "대사 설정 화면. 기존 캐릭터 설정 창에서 캐릭터별 대사(분류별 문장 목록)를 보고 추가·수정·삭제할 수 있는 화면. 분류는 평소/잡혔을 때/오래 잡혔을 때 세 가지로 공통이고 문장은 캐릭터마다 편집한다. 직접 등록한 캐릭터도 여기서 문장을 채울 수 있게 해 005의 \"등록 캐릭터는 말하지 않음\" 한계를 해소한다. 저장하면 앱을 다시 켜지 않아도 이후 혼잣말에 반영된다. 005의 문장 규칙(1~60자, 분류당 50개, 빈 문장 제외)을 입력 단계에서 검증해 이유를 보여 준다."

005에서 만든 대화셋(분류 3개, 캐릭터별 문장)을 사용자가 직접 편집하는 화면이다. 파일을 손으로 고치지 않고 캐릭터 설정 창에서 끝낸다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 캐릭터의 대사를 편집한다 (Priority: P1)

사용자가 캐릭터 설정 창의 캐릭터 목록에서 캐릭터를 골라 "대사 편집"을 열면, 평소·잡혔을 때·오래 잡혔을 때 세 분류의 문장 목록이 보인다. 문장을 추가·수정·삭제하고 저장하면 그 캐릭터가 이후 그 문장들로 말한다. 직접 등록한 캐릭터도 같은 방식으로 문장을 채울 수 있다.

**Why this priority**: 등록한 캐릭터가 말하지 않는 005의 한계를 해소하는 핵심 흐름이며, 이것만으로 가치가 완결된다.

**Independent Test**: 직접 등록한 캐릭터를 선택해 "평소"에 문장을 추가·저장하고 그 캐릭터를 사용하면 해당 문장이 혼잣말로 나온다.

**Acceptance Scenarios**:

1. **Given** 캐릭터 목록이 보일 때, **When** 한 캐릭터의 "대사 편집"을 열면, **Then** 세 분류와 각 분류의 현재 문장 목록이 보이고, 문장이 없는 분류는 비어 있는 것으로 보인다.
2. **Given** 대사 편집 화면에서, **When** 분류에 문장을 추가하고 저장하면, **Then** 저장되었다는 안내가 보이고 화면을 닫았다 다시 열어도 문장이 남아 있다.
3. **Given** 기존 문장이 있을 때, **When** 문장을 고치거나 지우고 저장하면, **Then** 변경이 반영되고 지운 문장은 더 이상 나오지 않는다.
4. **Given** 편집 중에 저장하지 않고 닫을 때, **When** 닫으려 하면, **Then** 변경이 저장되지 않았음을 알리고 저장·버리기·계속 편집 중 선택하게 한다.
5. **Given** 직접 등록한 캐릭터가 문장이 하나도 없는 상태일 때, **When** 사용자가 문장을 저장하면, **Then** 그 캐릭터가 활성이면 별도 재시작 없이 이후 혼잣말과 잡았을 때 대사에 반영된다.

---

### User Story 2 - 잘못된 입력은 이유와 함께 막는다 (Priority: P2)

문장 규칙(1~60자, 분류당 50개, 빈 문장 제외)을 어기면 저장 전에 어디가 왜 잘못되었는지 보이고, 규칙에 맞게 고칠 때까지 저장되지 않는다.

**Why this priority**: 규칙 위반을 조용히 버리면 사용자가 말이 안 나오는 이유를 알 수 없다. 편집이 가능해진 뒤에 필요한 보호 장치다.

**Independent Test**: 61자 문장, 빈 문장, 51번째 문장을 입력하면 각각 이유가 보이고 저장이 막힌다.

**Acceptance Scenarios**:

1. **Given** 문장 입력란이 비어 있거나 공백뿐일 때, **When** 저장하려 하면, **Then** 빈 문장은 저장하지 않으며 어느 분류인지와 이유가 보인다(빈 줄은 목록에서 자동으로 제외되고 안내만 한다).
2. **Given** 60자를 넘는 문장이 있을 때, **When** 입력하는 중이거나 저장하려 하면, **Then** 해당 문장에 글자 수 초과 이유와 현재 글자 수가 보이고 저장할 수 없다.
3. **Given** 한 분류에 문장이 50개를 넘을 때, **When** 저장하려 하면, **Then** 최대 개수(50개)를 넘었다는 이유와 현재 개수가 보이고 저장할 수 없다.
4. **Given** 같은 분류에 같은 문장이 중복으로 있을 때, **When** 저장하면, **Then** 중복은 하나로 합쳐 저장하고 합쳤다고 알린다.

---

### User Story 3 - 기본 문장으로 되돌린다 (Priority: P3)

기본 캐릭터와 샘플 캐릭터("빨간 모자", "나")는 처음부터 문장이 있다. 사용자가 이를 고쳐도 언제든 처음 문장으로 되돌릴 수 있다.

**Why this priority**: 편집이 가능해지면 실수를 되돌릴 수단이 필요하지만, 핵심 편집 흐름 없이는 의미가 없다.

**Independent Test**: 기본 캐릭터의 문장을 모두 지우고 저장한 뒤 "처음 문장으로 되돌리기"를 누르면 내장 문장이 돌아온다.

**Acceptance Scenarios**:

1. **Given** 기본 캐릭터 또는 샘플 캐릭터의 대사 편집 화면에서, **When** "처음 문장으로 되돌리기"를 선택하고 확인하면, **Then** 문장이 처음 상태로 돌아오고 이후 말하는 내용에 반영된다.
2. **Given** 직접 등록한 캐릭터일 때, **When** 화면을 열면, **Then** "처음 문장으로 되돌리기" 대신 "모두 비우기"가 제공되고, 비우면 그 캐릭터는 말하지 않는다.
3. **Given** 되돌리기를 눌렀을 때, **When** 확인 단계가 나타나면, **Then** 취소하면 아무것도 바뀌지 않는다.

---

### Edge Cases

- 편집 중인 캐릭터를 삭제하거나 다른 곳에서 바뀐 경우, 저장 시 사라진 캐릭터임을 알리고 저장하지 않는다.
- 저장 중 디스크 오류로 실패하면 변경 내용은 화면에 남고 실패 이유가 보인다. 기존 문장은 그대로여야 한다(반쯤 저장된 파일이 남지 않는다).
- 손상된 대화셋 파일을 가진 캐릭터는 빈 목록으로 열리고, 저장하면 정상 파일로 덮어쓴다.
- 문장에 줄바꿈이 들어가면 한 문장으로 두지 않고 줄 단위로 나눈다(말풍선은 한 줄 입력 기준).
- 활성 캐릭터가 아닌 캐릭터를 편집하는 중에는 지금 말하는 내용이 바뀌지 않는다.
- 저장하는 순간 이미 떠 있는 말풍선은 그대로 사라지고, 이후 발화부터 새 문장이 쓰인다.
- 설정 창이 닫히거나 앱이 종료되어도 저장한 문장은 유지된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 캐릭터 설정 창에서 기본 캐릭터를 포함한 모든 캐릭터의 대사를 편집하는 화면에 들어갈 수 있어야 한다.
- **FR-002**: 대사 편집 화면은 세 분류(평소, 잡혔을 때, 오래 잡혔을 때)를 모두 보여 주고, 각 분류의 문장을 추가·수정·삭제할 수 있어야 한다. 분류 목록은 사용자가 바꿀 수 없다.
- **FR-003**: 저장하면 변경은 앱을 다시 켜지 않아도 이후 혼잣말과 잡았을 때 대사에 반영되어야 한다. 활성 캐릭터가 아닌 캐릭터의 편집은 그 캐릭터가 활성이 되었을 때 반영된다.
- **FR-004**: 문장 규칙은 입력 단계에서 검증하고 위반한 문장 옆에 이유를 보여 주어야 한다: 앞뒤 공백을 지운 뒤 1~60자, 분류당 최대 50개, 빈 문장은 저장하지 않는다. 규칙을 어기는 상태에서는 저장할 수 없어야 한다.
- **FR-005**: 같은 분류의 중복 문장은 하나로 합쳐 저장하고, 합친 사실을 알려야 한다.
- **FR-006**: 입력한 줄바꿈은 문장 구분으로 처리해야 한다.
- **FR-007**: 저장하지 않은 변경이 있는 채 화면을 닫거나 다른 캐릭터로 이동하면 확인을 받아야 한다(저장, 버리기, 계속 편집).
- **FR-008**: 기본 캐릭터와 샘플 캐릭터는 "처음 문장으로 되돌리기"를 제공해야 하며, 되돌리기 전에 확인을 받아야 한다.
- **FR-009**: 직접 등록한 캐릭터는 "모두 비우기"를 제공해야 하고, 비운 캐릭터는 말하지 않는다(005 FR-013).
- **FR-010**: 저장은 실패하더라도 기존 문장을 잃지 않아야 하며, 실패하면 이유를 보여 주고 편집 내용은 화면에 남겨야 한다.
- **FR-011**: 캐릭터가 삭제되었거나 존재하지 않으면 저장을 거부하고 이유를 알려야 한다.
- **FR-012**: 캐릭터를 삭제하면 그 캐릭터의 편집된 문장도 함께 사라져야 한다(기존 005 동작 유지).
- **FR-013**: 손상된 대화셋을 가진 캐릭터도 화면은 빈 목록으로 열려야 하고 저장으로 정상화할 수 있어야 한다.

### Key Entities

- **대화셋 분류**: 005와 같은 세 분류. 모든 캐릭터가 공통이며 추가·삭제할 수 없다.
- **문장 목록**: 한 캐릭터가 한 분류에 가진 문장들. 사용자가 편집하며 005의 규칙을 따른다.
- **편집 중 초안**: 화면에만 있는 저장 전 문장 목록. 저장해야만 캐릭터의 대사가 바뀐다.
- **처음 문장**: 기본 캐릭터와 샘플 캐릭터가 앱과 함께 가진 원래 문장. 사용자 편집과 별개로 항상 되돌릴 수 있다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 설정 창을 연 뒤 1분 안에 등록한 캐릭터의 "평소" 분류에 문장 하나를 추가하고 저장할 수 있다.
- **SC-002**: 저장한 문장은 앱을 다시 켜지 않고 그 캐릭터의 다음 발화부터 반영된다(잡았을 때 대사는 즉시 확인 가능).
- **SC-003**: 규칙을 어긴 입력은 100% 저장 전에 걸러지고 위반 이유가 위반한 문장 옆에 보인다.
- **SC-004**: 저장 실패나 중간 종료 상황에서도 기존 문장이 손실되는 일이 없다.
- **SC-005**: 기본·샘플 캐릭터의 문장을 편집한 뒤 "처음 문장으로 되돌리기"로 원래 문장을 100% 복원할 수 있다.
- **SC-006**: 대사 편집 기능을 추가한 뒤에도 기존 캐릭터 등록·선택·삭제 검증과 말풍선·혼잣말 검증이 그대로 통과한다.

## Assumptions

- 편집 대상은 기본 캐릭터를 포함한 모든 캐릭터다. 기본 캐릭터와 샘플 캐릭터의 편집 결과는 사용자 데이터 폴더에 저장하며, 앱에 들어 있는 처음 문장은 바꾸지 않는다.
- 분류 이름은 화면에 한국어로 표시한다(평소 / 잡혔을 때 / 오래 잡혔을 때).
- 문장은 텍스트만 다룬다. 가져오기·내보내기, 캐릭터 간 복사, 문장 순서 변경, 문장별 가중치는 범위 밖이다.
- 한 번에 하나의 캐릭터만 편집한다.
- 문장 길이 60자·분류당 50개 한도는 005와 같고 이 기능에서 바꾸지 않는다.
- 설정 창이 여러 번 열리는 경우는 기존 동작(창 하나만 유지)을 따른다.
- 이번 검증은 macOS에서 수행한다. Windows는 후속이다.
