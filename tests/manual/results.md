## 성능 측정 (T037, macOS, 단일 디스플레이, 유휴 상태 60초 평균)

측정 방법: 실행 10초 후부터 60초 동안 앱의 모든 프로세스(main, GPU, 렌더러)의 CPU 시간 증가량을
합산해 평균 사용률을 구했다. 메모리는 `top`의 MEM 열 합계(RSS 합계는 공유 페이지를 중복 계산해
약 400MB로 과대하게 나온다).

| 시점 | CPU 평균 | 메모리 | 비고 |
|---|---|---|---|
| 최초 구현(전체 캔버스 매 프레임 지움, 60fps, 타이머 2개) | 약 25% | 약 280MB | |
| 변경 영역만 지움 + 32fps 제한 | 약 14% | 약 220MB | |
| 작은 캔버스를 `transform`으로 이동, 위치는 속도로 이어서 계산(IPC는 상태 변화 시만), 타이머 1개로 통합, 정지 중 재그리기 중단 | **9.0 ~ 9.9% (3회 평균 약 9.6%)** | 약 150MB | main 1.5~2.7%, GPU 3.6~5.0%, 렌더러 3.5~4% |
| 이미지 리소스(PNG) + CSS 애니메이션 전환(캔버스 제거, 걷기 프레임·이동 모두 compositor 처리) | **7.4 ~ 8.8%** (6회 중 5회, 평균 약 7.9%) / 11.1% 1회 | 약 150MB | main 약 2.5%, GPU 약 3.6%, 렌더러 약 2.6% |

- **SC-006(CPU 10% 이하, 메모리 300MB 이하)은 macOS에서 충족**한다. 이미지 리소스 전환 후 대부분 7~9%였으나 이동 시간 비율에 따라 흔들리며 한 번은 11.1%가 나왔다.
- SC-007(이동 중 30fps 이상): 이동은 compositor가 처리하고 걷기 프레임은 초당 약 14장(8장/0.56초)을 넘긴다.
- 정지 중에는 정지 자세 1장만 표시한다(숨쉬기 없음).
- 하드웨어 가속을 끄는 실험은 효과가 없어 적용하지 않았다.
- Windows는 측정하지 않았다.

## 성능 (T032, macOS, 디스플레이 2대, 설정 창 닫힌 유휴 상태, 60초 평균 1회)

|---|---|---|
| CPU 합계 | 약 8.1% (main 3.6, GPU 2.4, 렌더러 2.1) | SC-006(001): 10% 이하 — 충족 |
| 메모리 | 프로세스별 `top` MEM 합계 약 110MB | 300MB 이하 — 충족 |

- 1회 측정이라 이동 시간 비율에 따라 ±1~2%p 흔들릴 수 있다.
