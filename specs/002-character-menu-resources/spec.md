# Feature Specification: 우클릭 메뉴와 캐릭터 리소스 설정

**Feature Branch**: `002-character-menu-resources`

**Created**: 2026-10-22

**Status**: Draft

**Input**: User description: "우클릭 메뉴 화면과 첫 메뉴 기능인 캐릭터 리소스 등록·설정"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 캐릭터를 우클릭해 메뉴를 연다 (Priority: P1)

사용자가 화면 위의 캐릭터를 우클릭하면 메뉴가 나타난다. 메뉴에는 앱의 기능 목록이 있고, 이번에는
첫 항목으로 "캐릭터 설정"이 있다. 메뉴가 열려 있는 동안 캐릭터는 움직이지 않고 제자리에 있다가,
메뉴가 닫히면 그 자리에서 다시 돌아다닌다.

**Why this priority**: 우클릭 메뉴는 헌장의 핵심 상호작용 3종 중 하나이며, 이후 모든 앱 기능이
메뉴를 통해 제공되므로 가장 먼저 있어야 한다.

**Independent Test**: 캐릭터를 우클릭해 메뉴가 열리고 캐릭터가 멈추는지, 메뉴를 닫으면 같은
자리에서 다시 이동하는지 확인한다. 메뉴 항목이 "캐릭터 설정" 하나만 있어도 가치가 있다.

**Acceptance Scenarios**:

1. **Given** 캐릭터가 이동 중일 때, **When** 사용자가 캐릭터를 우클릭하면, **Then** 캐릭터 근처에
   메뉴가 나타나고 캐릭터는 즉시 멈춘다.
2. **Given** 메뉴가 열려 있을 때, **When** 사용자가 메뉴 밖을 클릭하거나 Esc 키를 누르면,
   **Then** 메뉴가 닫히고 캐릭터는 현재 위치에서 다시 자율 이동을 시작한다.
3. **Given** 캐릭터가 이동 중일 때, **When** 사용자가 캐릭터가 없는 영역을 우클릭하면, **Then**
   메뉴는 열리지 않고 우클릭은 아래 창에 그대로 전달된다.
4. **Given** 캐릭터가 화면 가장자리에 있을 때, **When** 우클릭하면, **Then** 메뉴는 화면 밖으로
   잘리지 않고 전체가 보인다.
5. **Given** 메뉴에서 "캐릭터 설정"을 선택하면, **Then** 캐릭터 설정 화면이 열린다.

---

### User Story 2 - 캐릭터 이미지를 등록한다 (Priority: P2)

사용자가 캐릭터 설정 화면에서 자신의 이미지 파일로 새 캐릭터를 등록한다. 이름을 정하고 걷는
모습과 정지한 모습의 이미지를 고르면, 등록 전에 미리보기로 어떻게 보이는지 확인할 수 있다.
조건에 맞지 않는 이미지는 이유와 함께 안내하고 등록되지 않는다.

**Why this priority**: 캐릭터를 바꿀 수 있어야 사용자가 앱을 자기 것으로 쓸 수 있고, 최종
디자인 이미지를 코드 수정 없이 넣을 수 있게 된다.

**Independent Test**: 올바른 이미지로 캐릭터를 등록하면 목록에 나타나고, 잘못된 이미지는 거부되고
이유가 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 캐릭터 설정 화면이 열려 있을 때, **When** 사용자가 이름을 입력하고 걷는 이미지와
   정지 이미지를 선택해 등록하면, **Then** 새 캐릭터가 등록된 캐릭터 목록에 나타난다.
2. **Given** 이미지를 선택한 상태에서, **When** 미리보기를 보면, **Then** 걷는 모습이 반복
   재생되고 정지 모습이 함께 보여 실제와 같은 크기와 방향으로 확인할 수 있다.
3. **Given** 걷는 이미지의 프레임 수를 지정해야 할 때, **When** 사용자가 프레임 수를 입력하면,
   **Then** 미리보기가 그 수대로 프레임을 나눠 재생한다.
4. **Given** 투명 배경이 아니거나 지원하지 않는 형식, 너무 큰 파일, 프레임 수와 맞지 않는
   이미지를 선택했을 때, **When** 등록을 시도하면, **Then** 등록되지 않고 무엇이 문제인지 알려
   준다.
5. **Given** 이름이 비어 있거나 이미 있는 이름일 때, **When** 등록을 시도하면, **Then** 등록되지
   않고 이유를 알려 준다.

---

### User Story 3 - 등록한 캐릭터를 선택하고 관리한다 (Priority: P3)

사용자가 등록한 캐릭터 중 하나를 선택하면 화면 위 캐릭터가 바로 그 모습으로 바뀐다. 선택은 앱을
다시 실행해도 유지된다. 등록한 캐릭터는 삭제할 수 있고, 언제든 기본 캐릭터로 되돌릴 수 있다.

**Why this priority**: 등록만 하고 적용할 수 없다면 의미가 없지만, 등록 기능이 먼저 있어야
선택할 대상이 생긴다.

**Independent Test**: 캐릭터 두 개를 등록하고 번갈아 선택해 화면 위 모습이 바뀌는지, 앱을 다시
실행해도 마지막 선택이 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 등록된 캐릭터가 둘 이상일 때, **When** 사용자가 하나를 선택하면, **Then** 화면 위
   캐릭터가 2초 안에 그 모습으로 바뀌고, 이동 중이던 위치와 방향은 유지된다.
2. **Given** 캐릭터를 선택한 상태에서, **When** 앱을 종료하고 다시 실행하면, **Then** 마지막에
   선택한 캐릭터가 나타난다.
3. **Given** 등록한 캐릭터가 있을 때, **When** 사용자가 삭제하면, **Then** 목록에서 사라지고,
   삭제한 캐릭터가 사용 중이었다면 기본 캐릭터로 바뀐다.
4. **Given** 어떤 캐릭터가 선택된 상태에서, **When** "기본 캐릭터로 되돌리기"를 선택하면,
   **Then** 앱에 포함된 기본 캐릭터로 바뀐다.
5. **Given** 사용 중인 캐릭터의 이미지 파일이 손상되거나 사라졌을 때, **When** 앱이 실행되면,
   **Then** 기본 캐릭터로 표시되고 설정 화면에 문제가 있음을 알려 준다.

---

### Edge Cases

- 메뉴가 열린 상태에서 모니터 구성이 바뀌거나 절전에 들어가도 메뉴와 캐릭터가 화면 밖에 남지
  않는다.
- 메뉴가 이미 열려 있을 때 캐릭터를 다시 우클릭하면 메뉴가 중복으로 열리지 않고 한 개만 유지된다.
- 캐릭터 설정 화면이 열려 있는 동안에도 캐릭터는 멈춰 있지 않아도 되며, 설정 화면을 닫지 않고
  화면 위 캐릭터가 바뀐 결과를 확인할 수 있다.
- 같은 이미지 파일로 여러 번 등록해도 서로 독립된 캐릭터로 취급한다.
- 등록 중에 원본 이미지 파일을 옮기거나 지워도 이미 등록된 캐릭터는 영향을 받지 않는다.
- 기본 캐릭터는 삭제할 수 없다.
- 전체 화면 앱이 실행 중일 때도 메뉴를 열 수 있고, 메뉴가 닫히면 이전 화면 상태로 돌아간다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사용자가 캐릭터를 우클릭하면 시스템은 캐릭터 근처에 메뉴를 표시해야 한다.
- **FR-002**: 캐릭터가 없는 영역의 우클릭은 메뉴를 열지 않고 아래 창에 그대로 전달되어야 한다.
- **FR-003**: 메뉴가 열려 있는 동안 캐릭터의 자율 이동은 멈춰야 하고, 메뉴가 닫히면 현재 위치에서
  재개되어야 한다.
- **FR-004**: 메뉴는 메뉴 밖 클릭 또는 Esc 키로 닫혀야 한다.
- **FR-005**: 메뉴는 항상 화면 안에 완전히 보이게 표시되어야 하며, 동시에 하나만 열려야 한다.
- **FR-006**: 메뉴에는 기능 항목 목록이 있어야 하고, 이번 기능에서는 "캐릭터 설정" 항목을 제공해야
  한다. 이후 기능은 같은 메뉴에 항목을 추가한다.
- **FR-007**: 캐릭터 설정 화면에서 사용자는 이름, 걷는 모습 이미지, 정지 모습 이미지를 지정해
  캐릭터를 등록할 수 있어야 한다.
- **FR-008**: 걷는 모습 이미지는 같은 크기의 프레임이 가로로 이어진 한 장의 이미지이며, 사용자는
  프레임 수를 지정할 수 있어야 한다.
- **FR-009**: 등록 전에 걷는 모습의 반복 재생과 정지 모습을 실제 표시 크기로 미리 볼 수 있어야 한다.
- **FR-010**: 이미지 조건(지원 형식, 투명 배경, 크기, 파일 용량, 프레임 수와의 정합성)에 맞지
  않거나 이름이 비어 있거나 중복이면 등록하지 않고 구체적인 이유를 알려야 한다.
- **FR-011**: 사용자는 등록한 캐릭터 목록에서 하나를 선택해 화면 위 캐릭터에 적용할 수 있어야
  하며, 적용 시 현재 위치와 이동 상태는 유지되어야 한다.
- **FR-012**: 선택한 캐릭터는 앱을 다시 실행해도 유지되어야 한다.
- **FR-013**: 사용자는 등록한 캐릭터를 삭제할 수 있어야 하며, 사용 중인 캐릭터를 삭제하면 기본
  캐릭터로 바뀌어야 한다.
- **FR-014**: 앱에 포함된 기본 캐릭터가 항상 있어야 하고, 사용자는 언제든 기본 캐릭터로 되돌릴 수
  있어야 하며, 기본 캐릭터는 삭제할 수 없어야 한다.
- **FR-015**: 선택된 캐릭터의 이미지를 읽을 수 없으면 기본 캐릭터로 표시하고 설정 화면에서 문제를
  알려야 한다.
- **FR-016**: 메뉴와 설정 기능은 macOS와 Windows에서 동일하게 동작해야 한다.

### Key Entities

- **메뉴**: 캐릭터 근처에 열리는 기능 목록. 항목 이름과 선택 시 열리는 화면을 가진다. 한 번에 하나만
  열린다.
- **캐릭터 세트**: 등록된 캐릭터 하나. 이름, 걷는 모습 이미지, 걷는 모습의 프레임 수, 정지 모습
  이미지, 등록 시각을 가진다. 기본 캐릭터는 앱에 포함된 읽기 전용 세트다.
- **활성 캐릭터**: 지금 화면 위에 표시되는 캐릭터 세트에 대한 선택. 앱을 다시 실행해도 유지된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 캐릭터를 우클릭하면 0.5초 안에 메뉴가 나타나고 캐릭터가 멈춘다.
- **SC-002**: 메뉴를 닫으면 1초 안에 캐릭터가 같은 위치에서 다시 이동을 시작한다.
- **SC-003**: 수동 검증에서 캐릭터가 없는 영역을 우클릭한 20회 모두 메뉴가 열리지 않고 아래 창에
  우클릭이 전달된다.
- **SC-004**: 사용자가 준비된 이미지 파일로 새 캐릭터를 등록해 적용하기까지 2분 안에 끝낼 수 있다.
- **SC-005**: 조건에 맞지 않는 이미지 10종(형식, 용량, 크기, 불투명, 프레임 수 불일치, 이름 오류
  등)을 등록하려 하면 10종 모두 등록되지 않고 이유가 표시된다.
- **SC-006**: 캐릭터를 선택하면 2초 안에 화면 위 캐릭터가 바뀐다.
- **SC-007**: 앱을 다시 실행했을 때 마지막에 선택한 캐릭터가 100% 유지된다(10회 반복).
- **SC-008**: 두 지원 OS(macOS, Windows) 모두에서 위 기준을 충족한다(검증 범위는 Assumptions 참조).

## Assumptions

- 메뉴는 캐릭터 근처에 뜨는 작은 목록이고, "캐릭터 설정"은 별도의 설정 화면(창)을 연다.
- 등록한 캐릭터는 여러 개를 저장할 수 있고 한 번에 하나만 활성화한다. 저장 개수 상한은 두지 않는다.
- 이미지는 사용자가 파일 선택으로 지정한다. 다른 곳에 있는 파일을 지정하지 않고, 등록 시 앱이 자체
  보관소에 복사해 원본과 독립된다.
- 이미지 조건의 구체적 값(지원 형식, 최대 용량, 프레임 크기 범위, 최대 프레임 수)은 plan 단계에서
  정한다. 기본 캐릭터가 쓰는 규격(투명 배경 이미지, 프레임 한 장은 정사각형, 걷는 모습은 8프레임)을
  기준으로 삼는다.
- 이미지는 오른쪽을 보는 한 방향만 등록하며 왼쪽은 앱이 반전해 표시한다.
- 걷기와 정지 두 모습만 다루며, 롱프레스로 집힌 모습처럼 다른 상태의 이미지는 해당 기능에서
  추가한다. 메뉴가 열려 있는 동안과 사용자 조작 중에는 정지 모습을 사용한다.
- 이미지 편집, 프레임 애니메이션 편집기, 캐릭터 이름 변경·순서 변경, 내보내기·공유는 이번
  범위에 포함하지 않는다.
- 롱프레스 이동, 그리고 "캐릭터 설정" 외의 메뉴 기능은 별도 기능이다.
- 이번 기능의 수동 검증은 앞선 기능과 같이 macOS 단일 디스플레이를 우선하며, Windows와 멀티
  모니터 검증은 후속으로 미룰 수 있다.
